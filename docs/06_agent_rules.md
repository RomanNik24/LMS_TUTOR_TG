# Правила написания кода для ИИ (Agent Rules): MY_LMS

Этот файл служит системным промптом для ИИ-агентов. При написании кода строго соблюдайте следующие правила.

## 1. Стиль кода и типизация
- **Type Hints:** Использование аннотаций типов (Type Hints) обязательно для всех функций, методов и классов (MyPy strict mode).
- **PEP 8 / Ruff:** Код должен соответствовать стандарту PEP 8. Используйте линтер Ruff для проверки.
- **Язык:** Имена переменных, классов, функций и коммитов пишутся строго на **английском** языке. Комментарии в коде — на **русском**.

## 2. Асинхронность
- **Никакого блокирующего I/O:** Использование синхронных библиотек (например, `requests`, `psycopg2`) запрещено.
- Используйте асинхронные аналоги: `httpx`, `asyncpg`, `asyncio`, `aiofiles`.

## 3. Обработка ошибок
- Оборачивайте критичные блоки (особенно работу с БД и внешними API) в блоки `try/except`.
- Используйте кастомные исключения (Custom Exceptions), определенные в папке `src/core/exceptions.py`.
- Логируйте все ошибки уровня `ERROR` с трейсбеком.

## 4. Порядок разработки (Инструкция для ИИ)
При получении задачи на разработку нового модуля, следуйте алгоритму:
1. Создание/Обновление моделей SQLAlchemy (`db/models/`).
2. Генерация миграции Alembic.
3. Написание методов в Репозиториях (`repositories/`).
4. Разработка бизнес-логики (`services/`).
5. Создание эндпоинта FastAPI (`api/`) или хэндлера Aiogram (`bot/`).
6. Создание UI-компонента во Flet (`webapp/`).
